# React Ecosystem Cookbook

Интерактивный справочник-книга рецептов по React: **45 тем в 8 разделах**. В каждой теме —
объяснение на русском, живой интерактивный пример, его исходный код, разбор работы кода,
типичные ловушки, нюансы и раздел «зачем/когда».

Это **учебный материал**, а не продакшен-приложение: примеры намеренно маленькие и изолированные,
каждый демонстрирует ровно одну идею. Код, имена компонентов и технические термины — на английском,
весь обучающий текст — на русском.

## Запуск

```bash
npm install     # зависимости
npm run dev     # dev-сервер → http://localhost:5173
npm test        # тесты (Vitest + Testing Library + jsdom)
npm run build   # продакшен-сборка в dist/
npm run preview # предпросмотр собранной версии
npm run typecheck
```

Нужен Node.js 18+.

### Как устроена тема

Каждая тема собирается фабрикой `topic()` в [src/content/types.ts](src/content/types.ts) из
одного объекта:

```ts
topic({
  id: 'jsx',
  title: 'JSX и рендеринг',
  summary: '…',              // строка для шапки и поиска
  Demo: JsxDemo,             // живой пример
  source: JsxDemoSrc,        // его исходный код (см. ?raw ниже)
  intro: `…`,                // 1. краткое объяснение
  how: `…`,                  // 4. как работает код
  compare: { … },            // (необязательно) ❌/✅ пара
  mistakes: `…`,             // 5. типичные ошибки
  nuances: `…`,              // 6. нюансы и практики
  when: `…`,                 // 7. зачем и когда
  alternatives: `…`,         // 8. простой и продвинутый варианты
})
```

Блоки показываются в этом порядке, а недоступные поля просто пропускаются.

### Исходный код показывается «как есть»

Пример импортируется дважды: как компонент и как строка через `?raw`:

```ts
import JsxDemo from '../examples/basics/JsxInspector.tsx?raw'   // текст файла
import JsxDemoComponent from '../examples/basics/JsxInspector'   // сам компонент
```

Поэтому код в UI **всегда совпадает** с тем, что реально выполняется, — правьте один файл,
и демо, и листинг обновятся вместе.

### Как добавить тему

1. Создайте файл примера: `src/examples/<раздел>/MyDemo.tsx` (по умолчанию `export default`).
2. Добавьте объект `topic({ … })` в соответствующий файл `src/content/<раздел>.tsx`.
3. Если нужен блок ❌/✅ — положите оба варианта в один файл и передайте `compare: { source, bad, good }`.
4. `npm run typecheck` — схема не даст забыть обязательные разделы текста.

## Технологии

React 19 · TypeScript 5 · Vite 7 · Vitest 3 + Testing Library · prism-react-renderer.

Строгий `tsconfig` (`strict`, `noUnusedLocals`) включён и для кода, и для контента: опечатка
в тексте темы или забытый импорт всплывут до сборки.

## Заметки

- `StrictMode` намеренно выключен: в dev он удваивал бы вызовы рендеров и эффектов, из-за чего
  счётчики в демонстрациях показывали бы «двойные» значения. Про StrictMode рассказано в теме
  «Жизненный цикл компонента».
- Раздел «React Server Components» объясняет концепцию моделью границы сервер/клиент —
  настоящего серверного рендеринга в проекте нет.
- Главный бандл тяжёлый (~800 КБ), потому что все исходники примеров вшиты в страницу через
  `?raw` — это осознанный компромисс справочника. Лениво грузится только `HeavyPanel`
  (тема «Lazy loading»), и в `vite build` он виден отдельным чанком.
